1. PROBLEM STATEMENT & MOTIVATION
================================================================================
Traditional travel planning is fragmented, overwhelming, and prone to error:
- Travelers must manually cross-reference 5-7 different platforms (Skyscanner, 
  Booking.com, AccuWeather, Google Maps, currency converters, and local blogs).
- Standard single-prompt LLMs (like raw ChatGPT) hallucinate flight numbers, 
  ignore budget constraints, output impossible timelines, and assume live 
  hotel availability that does not exist.
- Traditional sequential AI pipelines fail if one component crashes, lacking 
  dynamic routing, guardrails, and real-time external tool grounding.

THE MISSION:
Create a multi-agent orchestration framework where distinct AI specialists 
collaborate, validate each other's outputs, execute real-world tool calls via 
standardized protocols (MCP), and mandate human authorization before finalizing 
any mission plan.

================================================================================
2. CORE SOLUTION & ARCHITECTURAL PHILOSOPHY
================================================================================
AeroAgent solves this using four pillars of modern Agentic AI:
1. Specialization Over Generalization:
   Instead of one giant prompt trying to solve everything, distinct agents own 
   specific domains (Aviation, Lodging, Meteorology, Finance, Scheduling).
2. Dynamic Supervisor Routing:
   A Supervisor Agent analyzes user intent, applies input guardrails, extracts 
   structured trip constraints, and dynamically schedules only the agents needed.
3. Standardized Tool Calling via Model Context Protocol (MCP):
   Decoupled subprocess MCP servers expose live external capabilities (weather, 
   airport lookups, web search) over a standardized protocol.
4. Human-in-the-Loop (HITL) Safety Gate:
   The system interrupts execution before finalization, presenting an actionable 
   draft to the traveler (the "Captain") for verification or interactive revision.

5. DETAILED AGENT BREAKDOWN (WHO DOES WHAT?)
================================================================================

1. SUPERVISOR AGENT (agents.py -> supervisor_agent)
   - Function: Acts as the mission commander and gatekeeper.
   - Guardrail: Scans the raw user prompt. If the prompt is non-travel, offensive, 
     or empty, it halts immediately with a clear rejection reason.
   - Constraint Extractor: Parses origin, destination, duration (days/nights), 
     currency, and monetary budget into a clean JSON dictionary.
   - Router: Evaluates whether flight, hotel, and weather agents are needed 
     (e.g., skips flight agent if origin and destination are the same city).

2. FLIGHT AGENT (agents.py -> flight_agent)
   - Function: Gathers flight corridors, airlines, and airport intelligence.
   - Tools: Calls Aviation MCP tools (list_airports, list_airlines).
   - Reasoning: Synthesizes typical flight durations, recommended transit hubs, 
     departure windows, and realistic budget allocations without hallucinating 
     fake seat availability or non-existent direct routes.

3. HOTEL AGENT (agents.py -> hotel_agent)
   - Function: Analyzes lodging options, neighborhood suitability, and price tiers.
   - Tools: Queries Tavily Search MCP for live accommodation listings and reviews.
   - Reasoning: Filters results into 3 tiers (Luxury, Mid-range boutique, Budget) 
     and maps locations relative to transit hubs and major attractions.

4. WEATHER AGENT (agents.py -> weather_agent)
   - Function: Provides meteorological guidance and practical packing advice.
   - Tools: Invokes OpenWeatherMap MCP tools (current_weather, forecast).
   - Reliability Fallback: If external API keys are missing or invalid, the agent 
     automatically transitions to LLM seasonal climate intelligence rather than 
     failing or showing raw error codes.

5. BUDGET AGENT (agents.py -> budget_agent)
   - Function: Performs a strict financial audit of the proposed trip.
   - Reasoning: Compares estimated flights, lodging, local dining, transit, and 
     sightseeing expenses against the user's declared budget ceiling.
   - Output: Categorized percentage allocation table, contingency reserve (10-15%), 
     and actionable cost-saving recommendations.

6. ITINERARY AGENT (agents.py -> itinerary_agent)
   - Function: Synthesizes all intelligence into a cohesive, chronologically 
     sound day-by-day travel blueprint.
   - Structure: Morning, Afternoon, and Evening activities with realistic travel 
     times, walking distances, and culinary stops.
   - Output: Hands off a comprehensive Draft Plan to the Human Approval node.

7. HUMAN APPROVAL AGENT (agents.py -> human_approval_agent)
   - Function: Implements the safety circuit breaker using LangGraph `interrupt()`.
   - Halts the autonomous execution and waits for human input in the UI.

8. FINAL RESPONSE AGENT (agents.py -> final_response_agent)
   - Function: Converts the approved draft or incorporates user revisions into the 
     final executive travel dossier.
   - Post-Processing: Uses regex sanitization to eliminate raw HTML tags (e.g. <br>), 
     ensuring pristine Markdown tables and formatting.

6. TOOLING LAYER: MODEL CONTEXT PROTOCOL (MCP) EXPLAINED
================================================================================
What is MCP?
Model Context Protocol is an open standard created by Anthropic that decouples 
tools and data sources from the AI model. Instead of hardcoding API integrations 
inside LLM prompts, tools run as independent server processes communicating over 
standardized JSON-RPC via standard input/output (stdio).

How AeroAgent Uses MCP:
1. `weather_mcp_server.py`:
   - Runs as an independent process.
   - Exposes tools: `get_current_weather(city)` and `get_forecast(city)`.
2. `aviation_mcp_server.py`:
   - Exposes tools: `list_airports(country)` and `list_airlines()`.
3. `mcp_client.py`:
   - Manages asynchronous subprocess pipes (`stdio_client`).
   - Translates LangGraph agent tool calls into standardized MCP requests.
   - Automatically sanitizes environment variables to prevent subshell crashes.

Why this matters for your presentation:
"MCP ensures that our AI agents are modular. We can replace, upgrade, or add a 
new tool server (e.g., Uber API or Google Maps) without modifying a single line 
of our core graph orchestration logic."

7. STATE MANAGEMENT & FAULT-TOLERANT CHECKPOINTING
================================================================================
Central State Schema (state.py -> TravelState):
The entire workflow shares a strongly-typed TypedDict containing:
- `messages`: Conversation history
- `user_id` & `user_query`: Traveler identity and input string
- `trip_constraints`: Structured dictionary of destination, duration, budget
- `flight_results`, `hotel_results`, `weather_results`, `budget_results`
- `itinerary`: Draft schedule
- `approved` & `human_feedback`: Human-in-the-loop audit data
- `final_response`: Polished output

Persistence Layer (graph.py -> DiskMemorySaver):
- Problem: In Streamlit, every user interaction triggers a script re-run. Standard 
  in-memory savers (`MemorySaver`) lose thread states during reloads or restarts.
- Innovation: We engineered `DiskMemorySaver`, a persistent checkpointer that 
  serializes LangGraph checkpoints to disk (`.langgraph_checkpoints.pkl`).
- Benefit: If the server restarts or the browser refreshes during the Human Approval 
  stage, the thread state is instantly rehydrated without losing previous agent work.

8. HUMAN-IN-THE-LOOP (HITL) VERIFICATION PROTOCOL
================================================================================
Why HITL is crucial in Enterprise AI:
Fully autonomous agents can suffer from "drift" or make assumptions that do not 
match personal user tastes (e.g., scheduling a strenuous mountain hike for a 
traveler seeking a relaxing spa vacation).

How AeroAgent Implements HITL:
1. The graph compiles with an interruption point after `itinerary_agent`.
2. Execution pauses, returning an `__interrupt__` payload containing the draft.
3. Streamlit presents the "Captain's Approval Protocol" UI:
   - Radio Option A: "✅ Approve & Finalize Mission" -> Resumes to Final Response.
   - Radio Option B: "✏️ Request Custom Adjustments" -> Captures text feedback 
     (e.g., "Reduce hotel budget, replace Day 2 museum with street food tour").
4. On clicking "Confirm Decision", LangGraph uses `Command(resume={...})` to inject 
   the human's decision back into the active thread.
5. Resilient Fallback: If session checkpoints are cleared, a recovery handler 
   synthesizes the final output directly from the verified session state.

10. KEY ENGINEERING INNOVATIONS & RELIABILITY PATTERNS
================================================================================
1. Multi-Tier Model Fallback:
   If the primary Groq model (`openai/gpt-oss-120b`) encounters rate limits or 
   downtime, the system automatically falls back to `openai/gpt-oss-20b`, 
   `qwen/qwen3.8-27b`, or `Google Gemini 3.8 Flash`.
2. Graceful MCP Tool Degradation:
   If an external API key (such as OpenWeather or Tavily) is missing or exhausted, 
   the agent does not crash. It catches the exception and prompts the LLM to 
   synthesize seasonal guidance from internal knowledge.
3. HTML Tag Sanitization:
   LLMs frequently inject raw `<br>` tags inside Markdown table cells, which break 
   rendering in Streamlit. Custom regex pre-processors (`_clean_html`, `_clean_md`) 
   strip all invalid tags to maintain visual elegance.
4. Safe Dictionary Access:
   Every agent utilizes defensive `.get()` patterns to eliminate `KeyError` 
   exceptions regardless of thread rehydration state.

12. ANTICIPATED VIVA / EXAMINER QUESTIONS & MODEL ANSWERS
================================================================================

Q1: Why did you use LangGraph instead of traditional LangChain Sequential Chains?
A1: Traditional chains are rigid, linear DAGs. Real-world travel planning requires 
    dynamic branching, cyclic revision loops, conditional routing based on user 
    constraints, and first-class state checkpointing for Human-in-the-Loop interrupts. 
    LangGraph provides stateful cyclic graph execution natively.

Q2: What is the Model Context Protocol (MCP) and why is it better than standard tool calling?
A2: MCP standardizes how applications provide context and tools to LLMs. Standard 
    function calling tightly couples tool definitions inside application code. MCP 
    runs tools as isolated, modular subprocesses over JSON-RPC. This makes tools 
    language-agnostic, easily swappable, and secure.

Q3: What happens if an external API (like OpenWeatherMap or Tavily) fails or runs out of credits?
A3: Our agents implement graceful degradation. When an MCP tool call fails or returns 
    a 401/rate-limit error, the agent catches the exception and prompts the LLM 
    to provide seasonal climatology and historical knowledge instead of crashing 
    the entire graph.

Q4: How does the system handle state persistence during the human approval step?
A4: LangGraph uses an `interrupt()` node that halts graph execution and captures a 
    snapshot. We engineered a custom `DiskMemorySaver` that serializes these 
    checkpoints to disk using Python pickle. When the user responds in Streamlit, 
    the state is reloaded and resumed using `Command(resume=...)`.

Q5: Why did you choose Groq as your primary LLM engine?
A5: Groq provides custom LPU (Language Processing Unit) hardware inference speeds of 
    over 250-300 tokens per second. In a multi-agent system where 5-6 LLM calls occur 
    in sequence, high inference speed is critical to keep total workflow latency 
    under 8-12 seconds.

Q6: How do you prevent hallucinations in flight schedules and hotel bookings?
A6: Our system prompts strictly forbid agents from claiming confirmed seat or room 
    availability. Agents are instructed to provide typical flight corridors, average 
    historical price estimates, and verified neighborhoods, explicitly tagging all 
    figures as estimates.

Q7: What is the purpose of the Supervisor Agent?
A7: The Supervisor acts as the system coordinator and safety guardrail. It checks 
    input validity, extracts structured parameters (destination, budget, duration), 
    and determines which downstream agents are required, avoiding redundant calls.

Q8: How does the system prevent UI styling glitches with Markdown tables?
A8: Large Language Models often output `<br>` tags inside Markdown table cells to 
    simulate newlines. Streamlit's Markdown engine displays these as literal text. 
    We implemented regex post-processing functions (`_clean_html` and `_clean_md`) 
    that translate HTML breaks into clean Markdown line breaks.
